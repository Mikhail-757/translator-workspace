# ЛР1 — как устроен проект и что показать на защите

## За минуту

«Я сделал каркас кабинета переводчика на React и TypeScript. Ant Design даёт таблицы, формы, модальные окна и другие компоненты. React Router переключает девять экранов без перезагрузки. В этой лабораторной данные демонстрационные, в памяти браузера. Backend на FastAPI и PostgreSQL появятся в следующих работах. Память переводов и глоссарий пока работают без AI».

## Почему Ant Design?

В приложении много форм и таблиц. Готовые Form, Table, Modal, Drawer, Tag и Progress обеспечивают единый стиль и сокращают ручной код. ConfigProvider задаёт общий основной цвет, размеры и русскую локализацию. CSS отвечает за расположение блоков и адаптивность.

## За что отвечает код?

| `frontend/src/main.tsx` | Точка входа ReactDOM, тема, локаль, контекст и роутер |

## Что происходит при сохранении?

В редакторе текст поля сначала попадает в `drafts` через `useState`. При сохранении изменяются сегменты соответствующего документа в контексте, а прогресс рассчитывается по заполненным переводам. Переход между страницами не уничтожает контекст. Обновление вкладки запускает приложение заново и возвращает исходные mock-данные.

## Как работает маршрутизация?

React Router сопоставляет URL компоненту страницы. Link меняет URL без полной загрузки документа с сервера. Outlet вставляет выбранную страницу в общий layout. В production серверу нужна настройка возврата index.html для клиентских маршрутов.

## Зачем TypeScript?

Он проверяет типы ещё при сборке: например, статус документа может быть только `draft`, `in_review` или `approved`. Интерфейсы задают поля данных, а типизированные параметры помогают не перепутать документ и термин. Он не заменяет серверную проверку входных данных.

## Как выполнена работа?

Изучены методичка, дорожная карта и личный план AI/LLM. Выделены сценарии и маршруты, создан каркас Vite, затем общие layout и типизированные данные. Реализованы страницы и демодействия, добавлена адаптивная компоновка, выполнены сборка и проверки в Chrome. AI использован как помощник реализации; поведение подтверждается запуском и браузерными проверками. Это описание реальной последовательности, а не заявление о наличии Git-истории.

## Последовательность показа (5–7 минут)

1. Обзор: статистика, фильтр и поиск, переход в существующий документ.
2. Редактор: оригинал/перевод, подсказка для выбранного сегмента, сохранение. Попытка отправить неполный документ показывает предупреждение.
3. Новый документ: короткий текст → перевод → отправка → статус «На проверке».
4. Память: поиск английской/русской фразы, затем пустой результат.
5. Глоссарий: добавить, изменить, удалить с подтверждением.
6. Правки: одобрить, вернуть с комментарием, показать историю на вкладке «Все правки».
7. Мобильный вид: меню открывается кнопкой, оригинал и перевод располагаются друг под другом.

## Чего пока нет?

Настоящей авторизации, API, хранения в БД, автоматической сегментации, синхронизации очереди с документами, вычисления похожести и генерации перевода LLM. Не называйте демовход безопасной авторизацией, проценты совпадения — результатом алгоритма, а локальное сохранение — записью в БД. Эти части реализуются после ЛР1.
